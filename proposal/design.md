# 狼人殺第一天法官 - 系統設計與技術規範 (Design Document)

## 1. 產品定義 (Product Definition)
這是一個 **面對面狼人殺的自動化法官工具**，以純前端 Web App 形式運行。遊戲時將手機或平板放置桌面中央，由玩家自行操作夜間行動，程式負責所有流程控制、時間調度與結算邏輯，完全不需要真人法官。

### 核心功能
* **遊戲設定與靈活配置**：支援 6～16 人局，內建數十種預設板子配置（包含經典、夢魘攝夢、覺醒系列、第三方陣營等）。
* **全資料驅動 (Data-Driven)**：角色的查驗結果、技能目標數、免疫規則等皆由底層資料 (`data.json`) 定義，確保擴充與自訂的高彈性。
* **非同步夜晚流程**：自動依據隊列喚醒角色，採用精準的非同步語音播報（Web Speech API + Promise），確保流程不卡頓。
* **行動隊列與精準結算**：將所有操作收斂為行動隊列，處理連帶死亡鏈遞迴（殉情、攝夢連線、尋香綁定）及特殊屬性判定。

## 2. 視覺與互動設計規範 (UI/UX)
本應用程式專為「面對面桌遊情境」設計，確保在低光源與一般光源下傳遞裝置的流暢度與防呆性。

### 核心設計理念與限制
* **沉浸式的日夜氛圍**：深色背景搭配高對比色彩。
* **Mobile-First 限制**：外層容器加上 `max-width: 500px` 限制並水平置中，保持平板或手機單手持握時的最佳觸控手感與私密性（用雙手遮擋時更容易）。
* **彈性網格系統 (CSS Grid)**：號碼鍵盤使用 `grid-template-columns: repeat(4, 1fr)`，不管人數變化都能自動對齊成整齊的方陣。

### 色彩語意學 (Color Semantics)
* 🔴 **紅色系 (危險/攻擊/壞人)**：用於狼人刀人、女巫毒藥、查殺結果、出局或死亡名單。
* 🟢 **綠色系 (保護/成功/好人)**：用於守衛護盾、女巫解藥、金水查驗結果、平安夜提示。
* 🟡 **黃/橘色系 (提示/中立/神職)**：用於系統操作提示、狀態確認（如被恐懼、被冰凍）或特殊身分（如黑市商人裝備）。

### 互動與多感官回饋
* **聽覺主導 (Audio-First)**：語音指令穩定、簡短且明確。
* **視覺回饋**：按鈕按下時需有內縮動畫 (`transform: scale(0.92)`)，選中時則放大並改變邊框與底色。轉場採用 `fade-in` 處理。
* **觸覺回饋**：點擊號碼或確認送出時，結合 Web `navigator.vibrate` 給予輕微震動回饋。

### 防呆與隱私防護 (Action-Required)
* **強迫操作確認**：畫面上絕對不會同時出現「選擇目標」與「確認送出」。玩家必須先進行有效操作，對應的確認按鈕才會浮現，100% 避免手滑。
* **狀態隱蔽**：確認操作後畫面立刻切換為「請閉眼」，徹底隱藏操作足跡。

## 3. 架構與狀態管理 (State Management)
### 狀態樹 (`s` 物件)
所有的狀態變數集中於 `core.js` 的 `s` 物件中：
* **基礎與配置**：`s.total_players`, `s.current_board`, `s.ROLE_DICT`, `s.BOARD_CONFIGS`
* **玩家角色配置 (新增與擴充)**：
  * `s.player_roles`: 紀錄玩家的基礎身分對應。
  * `s.player_second_roles`: 紀錄玩家的第二身分（例如：開膛手傑克板子的狂熱粉、偵探等附加身分）。
  * `s.player_genders`: 紀錄玩家性別（`male` / `female`），用於性別綁定防呆。
  * `s.is_random_mode`: 布林值，標記當前設定是否開啟了「隨機發牌模式」。
  * `s.current_viewing_seat`: 數值，隨機發牌模式下追蹤當前正在查看身分的座位號碼。
  * `s.player_status`: 紀錄玩家當前狀態（如 `poisoned`, `injured`, `isWhiteCatFlipped` 等標記）。
* **行動隊列**：`s.night_actions` (所有夜晚操作統一寫入)。
* **狀態流轉與清單**：`s.night_status_flows`, `s.primary_killed`, `s.chain_killed`, `s.final_killed`。

### 開發準則 (Data-Driven & Strategy Pattern)
* **資料驅動**：角色的基本屬性集中在 `data.json`，避免散落在邏輯中。
* **策略模式**：角色行動邏輯透過 `actions.js` 獨立註冊，消除冗長 `if-else`。
* **統一非同步流程**：徹底使用 `async/await` 搭配 `delay()` 與 `speak()`，根除 `setTimeout` 競態條件。

## 4. 白天階段與法官面板 (Day Phase & Sheriff)
白天模組 (`day.js` / `sheriff.js`) 負責處理複雜的公開資訊結算與法官全局管理：
* **白天事件發布**：系統自動顯示昨夜死亡名單，並判定與公布熊的咆哮結果。
* **技能發動佇列**：管理白天因死亡而觸發的技能連鎖（如：獵人開槍、狼王開槍、覺醒狼王分槍、黑市商人武器發動等）。
* **警長競選流程**：處理上警名單選擇、隨機決定發言起點與方向，以及狼人自爆跳過機制。
* **特殊法官結算 (Edge Cases)**：
  * **延遲決策**：處理煉金魔女「法老之蛇」的白天發言後決策。
  * **票數干擾**：處理詭術師與魔術師的換票結算（確保白天放逐投票的票數能被正確對調）。
* **全局法官紀錄面板**：提供專屬 UI，一鍵查看所有玩家當前身上的標記（如被恐懼、被魅惑、中毒、護盾狀態等），及完整還原昨晚的詳細行動日誌。

## 5. 極端狀態與異常處理管線 (Pipeline & Edge Cases)
面對複雜技能的疊加，系統必須遵循嚴格的管線化與模擬機制：
* **異常狀態等時模擬**：當玩家處於「被恐懼 (夢魘)」或「被冰凍 (企鵝)」狀態時，系統仍會叫醒該玩家並顯示專屬封鎖畫面，玩家依然需要點擊「確認並閉眼」，徹底阻絕利用時間差或「某人沒被叫醒」獲取場外資訊的可能。
* **管線化死亡結算 (Pipeline)**：`day.js` 中的死亡結算必須分層處理。所有的護盾與免疫判定必須在加入 `primary_killed` 清單前完成（順序：失效 -> 防護 -> 查驗致死 -> 狼刀/毒藥 -> 反傷 -> 連鎖死亡）。
* **絕對擊殺判定**：特殊技能享有最高優先級，例如潘朵拉魔盒開出的「刀」無視女巫的解藥，結算時需直接穿透防護。
* **遞迴連帶死亡鏈**：透過 `handleChainDeaths()` 遞迴處理連帶死亡鏈（包含邱比特殉情、攝夢人連線出局、許仙尋香綁定、鬼魅新娘等），直到陣列中沒有新增的死亡者為止。
